# Rebirth Protocol — Prototype 0.7

GDD v0.2(`../GDD/ROCKMAN_X9_GDD_v0.2.md`)의 시스템을 검증하는 Godot 4.7 프로토타입입니다.
주인공 3인과 히든 보스 이클립스는 **오리지널 픽셀 아트 스프라이트**(`art/characters/`), 나머지 적·보스는 코드로 그린 그림에 픽셀 아트 셰이더를 입힌 것입니다. 타일은 스테이지마다 다른 픽셀 아트 타일셋, 배경에는 2.5D 원근 소품 층이 있습니다(아래 "그래픽"). 원작 캐릭터·이름·스프라이트·음악은 사용하지 않습니다.
효과음과 음악도 음원 파일 없이 **코드로 합성한 오리지널**입니다.

## 실행

```bash
godot --path game
```

에디터로 열기: `godot -e --path game` (또는 Godot 앱에서 `game/project.godot` 열기)

흐름: 타이틀(새 게임 / 이어하기) → 스테이지 선택(훈련 시설 · 프리즘 게코 · 아머 랩) → 출격 멤버 선택 → 스테이지 → 클리어 후 스테이지 선택.
저장 파일: `~/Library/Application Support/Godot/app_userdata/Rebirth Protocol (Prototype)/save.json` (옵션은 같은 폴더의 `settings.cfg`)

**옵션** (타이틀 · 일시정지): 음악·효과음 음량(0–10, **음악은 기본 꺼짐** — 켜려면 옵션에서 올리세요), 난이도(쉬움: 받는 피해 ×0.5 / 보통 / 어려움: ×1.5), 화면 흔들림, 밝은 깜박임 줄이기(보스 피격 섬광·번개), 전체 화면, 조작 안내. ← → 로 바꾸면 바로 저장됩니다.

### macOS 앱으로 내보내기

`export_presets.cfg`에 macOS 설정이 있습니다(universal: Apple Silicon + Intel, ad-hoc 서명). 레벨 파일 `levels/*.txt`는 Godot 리소스가 아니라서 프리셋의 `include_filter`로 직접 넣고, `tests/`는 뺍니다.

1. **Godot 4.7.2 내보내기 템플릿 설치** (한 번만). 에디터의 *편집기 → 내보내기 템플릿 관리*로 받거나, 공식 릴리스(1.28GB)에서 macOS 템플릿만 꺼내 넣습니다:

   ```bash
   curl -LO https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_export_templates.tpz
   T=~/Library/Application\ Support/Godot/export_templates/4.7.2.stable
   mkdir -p "$T" && unzip -j Godot_v4.7.2-stable_export_templates.tpz templates/macos.zip templates/version.txt -d "$T"
   ```

   (받은 파일은 같은 릴리스의 `SHA512-SUMS.txt`로 확인할 수 있습니다.)

2. **빌드** → `game/export/RebirthProtocol.app` (약 164MB, 저장소에는 올리지 않음)

   ```bash
   mkdir -p game/export && godot --headless --path game --export-release "macOS" export/RebirthProtocol.app
   ```

3. **실행 확인**: `open game/export/RebirthProtocol.app`. 빌드된 앱에서도 스크린샷 투어가 됩니다:
   `"game/export/RebirthProtocol.app/Contents/MacOS/Rebirth Protocol (Prototype)" -- --gallery=/tmp/rp_shots`

ad-hoc 서명이라 빌드한 맥에서는 바로 열리지만, 다른 맥에서 내려받아 열면 Gatekeeper가 막습니다(*시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기*). 정식 배포에는 Apple Developer ID 서명과 공증이 필요합니다.

## 캐릭터와 태그 (GDD v0.2 §6 — 오리지널 캐릭터)

기획서의 엑스·제로·액셀 역할을 오리지널 캐릭터로 구현했습니다. 스테이지 전에 2명을 고르고, Tab 으로 그 자리에서 교대합니다.

| 캐릭터 | 역할 | 조작 |
|---|---|---|
| **IX** | 버스터·아머·특수무기 | 3단 차지, 아머 8파츠, 보스 무기 6종(Q/E) |
| **SABLE** | 세이버 | 지상 3연격, 공중 베기, 대시 찌르기, 벽 베기, 패링(V)→반격. 적 탄도 베어 없앨 수 있음. 검술 Q/E: 섬광류(빠름·공중 2회) / 파쇄류(강함·3타가 균열벽 파괴) / 반격류(패링 시간 2배·반격 강화) |
| **ECHO** | 연사·복제 | 8방향 연사(↑↓ 조준), 공중 점프 유지로 호버, V 복제탄 → 처치한 적 데이터로 변신(V): 워커→소형체(1칸 통로 통과), 터렛→3갈래 연사 |

- 교대 직전 0.6초 안에 공격을 맞히면 **태그 콤보**(교대 캐릭터의 무적 돌진).
- 대기 중인 파트너는 2초마다 HP 1 회복. 한 명이 쓰러지면 파트너가 이어받고, 둘 다 쓰러지거나 구덩이·가시에 닿으면 체크포인트부터 다시.

## 그래픽 — 캐릭터 스프라이트 (X6식 32비트 스프라이트 방식)

세 주인공과 이클립스는 `art/characters/<id>/`의 픽셀 아트 스프라이트 시트로 그립니다. 모두 오리지널 디자인이며, 록맨 X4~X6 시절 32비트 스프라이트의 **만드는 방식**(기본 몸 위에 아머 파츠를 겹치는 구조, 많은 동작 프레임, 색 외곽선, 스프라이트 이펙트)을 따릅니다. 원작 캐릭터의 모양은 따라 하지 않습니다.

| 캐릭터 | 디자인 |
|---|---|
| **IX** | 흰 프레임·청록 코어·금색 바이저. 아머마다 팔레트를 바꾸고 파츠를 덧붙임 — 뱅가드(파랑·진홍: 앞뿔, 가슴 갈매기 무늬, 등 추진기, 큰 어깨, 블록 버스터, 뒤꿈치 추진기), 에어로(흰색·민트: 날개 핀, 칼라 줄무늬, 등 날개, 지느러미 어깨, 통풍구 버스터, 발목 핀), 얼티밋(보라·금) |
| **SABLE** | 강철색 검사, 주황 볏, 가면과 청록 눈 슬릿, 등에 멘 세이버 |
| **ECHO** | 작은 청록 사수, 넓은 금색 바이저, 쌍 안테나, 보라 코어, 쌍권총, 소형체 |
| **ECLIPSE** | IX의 어두운 쌍둥이(흑연색·자홍 볏), 리미터 해제·잔상용 줄 |

- **손으로 찍은 파츠** (`tools/sprites/ix_kit.gd` 등): 헬멧·가슴·부츠(평발/발끝)·어깨·버스터는 팔레트 번호로 한 칸씩 찍은 그림이고, 뼈대는 위치만 잡고 관절 팔다리를 그 사이에 그립니다. 가슴은 기울기만큼 줄을 밀어(시어) 숙이고, 아머 종류는 팔레트 교체 + 덧붙임 조각입니다.
- **색 외곽선**: 바깥 외곽선이 감싸는 색의 진한 색이라 32비트 스프라이트처럼 부드럽게 읽힙니다.
- **애니메이션 53프레임**: 대기 6 · 달리기 시작 2 + 달리기 12 · 대시 시작 2 + 대시 2 + 브레이크 2 · 도약·상승·정점·낙하 · 착지 2 · 벽 미끄러짐·벽 차기 · 피격 · 비행 · 활공 · 돌진 · 급강하 · **승리 포즈**(미션 완료) · **워프 인**(스테이지 시작 때 빛기둥이 내려온 뒤 착지).
- **스프라이트 이펙트** (`art/fx/`, `tools/bake_fx.gd`): 대시 연기 · 착지 먼지 · 벽 불꽃 · 머즐 플래시(차지샷은 금색) · 차지 오라, 사라질 때는 4×4 순서 디더링.
- **무기 팔**: 사격 중엔 앞팔이 버스터로, SABLE은 16방향 세이버 팔, ECHO는 16방향 권총 팔.

**다시 굽기:**

```bash
godot --headless --path game -s res://tools/bake_characters.gd
godot --headless --path game -s res://tools/bake_fx.gd
```

`-- --preview=/절대/경로`를 붙이면 확대한 확인용 시트를 저장합니다.

### 손 보정 (도트 작가 작업)

X6급 마무리는 결국 손으로 찍은 도트가 필요합니다. 다시 구워도 손 작업이 사라지지 않도록 **보정 레이어**를 씁니다.

1. 고칠 시트(예: `art/characters/ix/head.png`)를 같은 이름으로 `art/characters/ix/retouch/`에 복사합니다.
2. Aseprite 등에서 고칠 칸만 그립니다(칸 64×56, 가로 = 프레임, 세로 = 아머 종류). 손대지 않을 곳은 투명으로 지웁니다.
3. 다시 구우면 보정 레이어의 불투명 픽셀이 위에 덮이고, **순수 자홍(#ff00ff)** 픽셀은 원래 픽셀을 지웁니다.

`retouch/` 폴더는 `.gdignore`가 있어 게임에 포함되지 않습니다.

- **픽셀 셰이딩 레이어:** 적·보스와 그들이 만든 탄·이펙트는 레벨의 `Actors` CanvasGroup 안에 있고, `scripts/fx/pixel_shade.gdshader`가 캐릭터 스프라이트와 같은 1px 외곽선·위쪽 빛·아래쪽 그림자·안쪽 선을 입힙니다. 반투명한 예고 표시·광원은 그대로 통과합니다. 이미 음영이 들어간 스프라이트는 알파 0.98로 그려 셰이더를 건너뜁니다.
- **보스 9종:** 각자 상태에 따라 움직이는 코드 드로잉을 유지한 채, 부위마다 밝은 면·중간·그림자 면·반짝임·패널선을 더해 다시 그렸습니다(공격 판정·타이밍·예고는 그대로).
- **이클립스:** IX의 어두운 쌍둥이라는 설정에 맞춰 캐릭터와 같은 뼈대·34포즈 스프라이트(`art/characters/eclipse/`, 리미터 해제·잔상용 줄 포함)를 씁니다.
- **잡몹:** 크롤러(마디 등껍질·관절 다리·센서 눈), 터렛(볼트 받침·음영 돔·조준 눈).
### 타일·배경

- **타일셋 9종** (`art/tiles/<테마>.png`, `tools/bake_tiles.gd`): 훈련 시설 금속 패널 · 프리즘 게코 수정 박힌 돌 · 그래비티 앨버트로스 경고 줄무늬 선체판 · 솔라 페넥 사암 벽돌과 태양전지 · 크라이오 나왈 서리 강철과 눈·고드름 · 테라 팽골린 암석 지층 · 펄스 시카다 전기 그레이팅 · 에덴 코어 회로 블록 · 얼음(공용).
  - 칸마다 위·오른쪽·아래·왼쪽 중 드러난 면(16가지)에 맞춰 외곽선·빛 경사·윗면 마감·아랫면 그림자를 고르고, 위치에 따라 무늬 변형 4종 중 하나를 씁니다. 벽 깊숙한 칸은 어둡게 칠해 표면이 먼저 읽힙니다.
  - 다시 굽기: `godot --headless --path game -s res://tools/bake_tiles.gd` (`-- --preview=/절대/경로`로 확인용 그림). PNG는 손으로 고쳐도 됩니다(16×16 칸, 가로 16 × 세로 4).
- **2.5D 소품 층** (`scripts/level/backdrops/depth_props.gd`, GDD §7-1): 시차 배경 앞, 플레이 필드 바로 뒤에 상자형 소품(빌딩·수정 기둥·트러스·탱크·얼음 기둥·터널 지지대·송전탑·데이터 모놀리스)을 카메라 기준 1점 투시로 매 프레임 그립니다. 움직이면 옆면·윗면이 돌아가 보이고, 충돌·조작은 2D 그대로입니다. 깊이에 따라 안개색으로 흐려지고, 윗면은 발판처럼 보이지 않게 옆면에 가깝게 둡니다.

### 연출 (GDD §7-2)

- **타이틀:** 에덴 링크 궤도 구조물 배경(`backdrops/title.gd`) — 행성과 그 둘레의 궤도 링(뒤쪽 반은 행성 뒤로, 앞쪽 반은 앞으로), 모듈·업링크 빔·빛나는 코어 허브. 왼쪽 아래 발판에 IX·SABLE·ECHO가 서 있습니다.
- **스테이지 선택:** 왼쪽에 고른 보스의 초상화(2배)와 상태(✓ 클리어 · ▲ 환경 변화 · ◈ 신호), 오른쪽에 목록과 **EDEN LINK 지역 지도**(스테이지마다 코어로 이어진 노드, 고른 노드 강조). 보스가 없는 줄은 잡음 화면.
- **보스 등장 컷인:** 레터박스가 닫히고, 줄무늬 띠가 미끄러져 들어와 초상화 · WARNING(히든은 UNKNOWN SIGNAL) · 보스 이름 · 지역 설명을 보여 준 뒤 빠집니다(약 1.6초, 조작 잠금 시간 안).
- **보스 초상화** `art/portraits/<id>.png` (80×56)는 게임 안에서 찍습니다. 보스 그림을 바꿨다면 다시 찍으세요(창이 열립니다):

```bash
godot --path game -- --portraits=$(pwd)/game/art/portraits
```

### 화면 버퍼

- 메인 화면은 `rendering/viewport/transparent_background=true`로 8비트 알파 버퍼를 씁니다. 기본 버퍼(RGB10_A2)는 알파가 2비트라 레이어 안의 반투명 효과가 0·⅓·⅔·1로 뭉개지고, 옅은 광원은 사라졌습니다. 창 자체는 투명해지지 않으며, 모든 화면이 배경으로 덮여 있는지 스크린샷으로 확인했습니다.

## 특수무기 (GDD v0.2 §5)

보스를 쓰러뜨리면 IX가 그 보스의 무기를 얻습니다(F2 디버그로 한꺼번에 해금 가능). 무기 에너지 28, 적이 떨어뜨리는 노란 캡슐로 회복.

| 무기 | 보스 | 동작 |
|---|---|---|
| REFRACTION BEAM | 프리즘 게코 | 빠른 광탄, 벽에서 2번 반사 |
| GRAVITY WING | 그래비티 앨버트로스 | 느린 중력 구체: 적 탄을 끌어당겨 지우고 다단 히트 |
| HEAT MIRAGE | 솔라 페넥 | 바닥을 달리는 열파, 관통 |
| FREEZE LANCE | 크라이오 나왈 | 관통 창, 적을 2.5초 동결 |
| CORE DRILL | 테라 팽골린 | 근거리 드릴, 다단 히트, 균열벽 파괴 |
| PULSE RING | 펄스 시카다 | IX 주변으로 퍼지는 고리, 적 탄 제거. **프리즘 게코의 약점**(2.5배 + 패턴 중단, 2.5초 쿨다운) |

## 아머 시스템 (GDD v0.2 §4)

슬롯 4개(HEAD/BODY/ARM/LEG) × 3택(뉴트럴/뱅가드/에어로) = 81조합. 파츠는 스테이지의 캡슐로 해금하고, 켜진 체크포인트나 스테이지 선택의 아머 랩에서 바꿉니다. 프리셋 3칸.

| 파츠 | 뱅가드 | 에어로 |
|---|---|---|
| HEAD | 균열벽·가짜 발판 표시, 일반탄 근거리 유도 | 공중에서도 코어 회복 |
| BODY | 대시 중 피해 50% 감소, 넉백 없음 | 점프 유지로 활공, 공중 피해 25% 감소 |
| ARM | 차지샷이 균열벽 파괴, 풀차지 전체 관통 | 차지샷 3갈래 확산 |
| LEG | 대시 중 재입력으로 2연속 대시, 대시 몸통 공격 | 공중 대시 1회, 공중에서 점프 재입력으로 비행(코어 소모) |

세트: 같은 계열 2파츠(뱅가드 대시 거리 +15% / 에어로 코어 회복 +50%), 하이브리드 2+2(듀얼 코어: 대시 점프 후 공중 대시 +1), 풀세트 필살기(뱅가드 OVERDRIVE RUSH / 에어로 SKY BREAKER).

GDD와 다른 점: 뱅가드 2파츠 효과를 "대시 재사용 단축" 대신 "대시 거리 +15%"로 구현(대시에 쿨다운이 없어서). 전투 중 교체와 얼티밋 아머 IX(히든 보스 보상)는 아직 없음.

## 스테이지 (로드맵 5단계)

스테이지는 `levels/*.txt` 파일 하나씩이고, 맨 위 `; @key` 머리말로 스테이지 선택 목록·보스·무기·잠금 조건이 정해집니다. 타일 범례와 레벨 디자인 기준은 [levels/README.md](levels/README.md).

| 스테이지 | 기믹 | 보스 (약점) | 얻는 무기 |
|---|---|---|---|
| 훈련 시설 | 기본 조작, 파츠 캡슐 7개, 균열벽·소형체 통로 뒤 HP 증가 | — | — |
| 프리즘 게코 | 반사 레이저, 가짜 발판, 홀로그램 발판 | 프리즘 게코 (PULSE RING) | REFRACTION BEAM |
| 그래비티 앨버트로스 | 저중력, 상승 기류, 이동 발판, 에어로 LEG 캡슐 | 그래비티 앨버트로스 (REFRACTION BEAM) | GRAVITY WING |
| 솔라 페넥 | 열기 분출구(거울로 꺾임), 이동 발판, 붕괴 모래 | 솔라 페넥 (GRAVITY WING) | HEAT MIRAGE |
| 크라이오 나왈 | 물(수중 점프), 얼음, 가시 | 크라이오 나왈 (HEAT MIRAGE) | FREEZE LANCE |
| 테라 팽골린 | 붕괴 터널, 갈림길, 자기부상 열차 발판 | 테라 팽골린 (FREEZE LANCE) | CORE DRILL |
| 펄스 시카다 | 박자 전기 바닥, 레이저 중계, 송전탑 벽차기 | 펄스 시카다 (CORE DRILL) | PULSE RING |
| 에덴 코어 (최종) | 모든 기믹 복합 · 보스 6명 격파 후 열림 | 아르카 (약점 없음, 2페이즈) | — |

**히든 보스 (GDD §5-3)**

| 보스 | 위치 | 조건 | 보상 |
|---|---|---|---|
| 이클립스 | 테라 팽골린 — 균열벽 너머 지하 분기 | 보스 3명 격파 | **얼티밋 아머 IX** · 확장 엔딩 |
| 프래그먼트 Λ | 그래비티 앨버트로스 — 상층 중계기 (에어로 LEG 비행으로만 도달) | 보스 6명 + 이클립스 | 진엔딩 |

**스테이지 연동 (GDD §5-4):** 보스를 쓰러뜨리면 다른 스테이지의 지형이 바뀝니다. 스테이지 선택 화면에 ▲(환경 변화)와 ◈(미확인 신호)로 표시되고, 바뀐 스테이지에 들어가면 안내가 뜹니다. 바뀌기 전에만 있는 보상은 없습니다.

| 조건 | 바뀌는 곳 | 변화 |
|---|---|---|
| 펄스 시카다 격파 | 테라 팽골린 | 전력 복구 — 봉인 게이트가 열리고 자기부상 열차 발판 구간 개통, 끝에 HP 증가 |
| 크라이오 나왈 격파 | 솔라 페넥 | 발전소 냉각 — 열기 분출구 9 → 5개, 숨은 통로 위 HP 증가 |
| 그래비티 앨버트로스 격파 | 그래비티 앨버트로스 | 중력 안정화 — 상층(프래그먼트 Λ) 해치 개방 |
| 뱅가드 ARM | 펄스 시카다 | 균열벽 뒤 재방문 HP 증가 |
| 에어로 LEG | 크라이오 나왈 | 격납고 위 높은 선반의 재방문 HP 증가 |

**배경:** 스테이지마다 다른 원경(데이터 도시 · 광학 보관소 · 궤도 조선소 · 사막 발전소 · 극지 바다 · 지하 철도 · 폭풍 변전소 · 디지털 코어), 2–3겹 패럴랙스.

**사운드:** 효과음 37종, 음악 17곡(타이틀·선택·스토리·스테이지 8곡·보스 3곡·엔딩, 클리어·보스 등장 징글). 백그라운드 스레드에서 합성해 메인 스레드 비용은 프레임당 0.4ms 이하.

- 이클립스: IX의 움직임을 따라 하는 미러 보스. 같은 무기를 3번 연속 맞으면 그 무기에 내성(ADAPT).
- 프래그먼트 Λ: 코어가 열린 순간에만 피해. 2페이즈에 바닥에서 파편이 솟고 끌어당김.

**얼티밋 아머 IX:** 아머 랩의 FRAME 행에서 PARTS ↔ ULTIMATE 전환. 노바 스트라이크 IX(V, 코어 100), 잔류 플라즈마 풀차지, 공중 대시·호버. 대신 균열벽·활공·비행 같은 탐험 능력은 없음.

**스토리:** 새 게임 프롤로그 → 보스 3명 격파 후 중간 이벤트 → 에덴 코어 클리어 시 엔딩(일반 / 확장 = 이클립스 / 진 = 프래그먼트 Λ) + 크레딧. 모두 오리지널 문구.

## 테스트

```bash
for t in run_tests armor_combos boss_hidden_test boss_solar_fennec_test boss_arca_test boss_pulse_cicada_test boss_cryo_narwhal_test boss_terra_pangolin_test boss_gravity_albatross_test stage_link_test backdrop_test audio_test; do godot --headless --fixed-fps 60 --path game -s res://tests/$t.gd | tail -1; done
```

- `run_tests.gd` (114개): 이동·전투·아머·파트너·특수무기·기믹·저장, 그리고 **등록된 모든 스테이지와 보스를 자동으로 불러와 검사**하는 통합 테스트.
- `armor_combos.gd`: 81조합 규칙 + 동시 물리 시뮬레이션.
- `boss_*_test.gd` (7개, 313개 검사): 스테이지 구조, 뉴트럴 IX로 필수 경로 주파, 보스 패턴·페이즈·약점·경직 쿨다운·사망, 회피 가능성.
- `stage_link_test.gd` (45개): 스테이지 연동 전·후 지형, 새 보상이 바뀐 뒤에만 닿는지(스크립트 플레이어로 실제 주파), 필수 경로 불변.
- `backdrop_test.gd` (39개): 배경 8종 생성·전환·누수·깜박임 옵션·비용.
- `audio_test.gd` (41개): 효과음·음악 전부 합성, 길이·무음·루프, 시작·프레임 비용.

게임 흐름(main.gd)이 필요한 점검은 `-s` 대신 실행 인자로 돌립니다:

```bash
godot --headless --fixed-fps 60 --path game -- --flowcheck
```

```bash
godot --headless --fixed-fps 60 --path game -- --perfcheck
```

`--flowcheck` (44개): 조건부 타일, `cleared:` 조건, 옵션 메뉴 입력·저장 값, 스테이지 선택 스크롤과 ▲ / ◈ 표시, READY·난이도·화면 흔들림, 일시정지 옵션, 보스 음악 전환. `--perfcheck`: 스테이지마다 10초 동안 달리고 쏘며 프레임 비용을 잽니다(헤드리스는 그리기 비용 제외, 창 모드에서는 그리기 호출 수도 표시).

스크린샷:

```bash
godot --path game -- --autoshot=/tmp/rp_shots
```

```bash
godot --path game -- --gallery=/tmp/rp_gallery
```

`--autoshot`은 시스템별 연출 투어, `--gallery`는 모든 스테이지의 시작·체크포인트·보스(히든 포함) 화면을 찍습니다. 둘 다 저장 파일은 건드리지 않고, 소리도 내지 않습니다.
